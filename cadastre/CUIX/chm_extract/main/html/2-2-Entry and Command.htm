Program Entry and Command Registration

Sample Code Analysis (C# Example)

In the previous chapter "First .NET Program," we mentioned the following sample code:

    // Namespace references
    using System;
    using System.Collections.Generic;
    using System.Linq;
    using System.Text;
    using System.Threading.Tasks;
    using ZwSoft.ZwCAD.Runtime;
    using ZwSoft.ZwCAD.ApplicationServices;
    using ZwSoft.ZwCAD.Geometry;
    using ZwSoft.ZwCAD.DatabaseServices;
    using ZwSoft.ZwCAD.EditorInput;
    
    // Assembly attributes
    [assembly: ExtensionApplication(typeof(ZrxDotNetCSProject.PlugInApplication))]
    [assembly: CommandClass(typeof(ZrxDotNetCSProject.Commands))]

    namespace ZrxDotNetCSProject
    {
        public class PlugInApplication : IExtensionApplication
        {
            // Callback function during program initialization
            public void Initialize()
            {
                // Add your initialize code here.
            }

            // Callback function during program termination
            public void Terminate()
            {
                // Add your uninitialize code here.
            }
        }
    
        class Commands
        {
            // Command definition
            [CommandMethod("HelloCS")]
            static public void HelloCS()
            {
                Database db = HostApplicationServices.WorkingDatabase;
                Document doc = Application.DocumentManager.GetDocument(db);
                ZwSoft.ZwCAD.EditorInput.Editor ed = doc.Editor;
    
                ed.WriteMessage("\nHello World!");
            }
        }       
    }

This is the simplest ZWCAD .NET development program. Note that if using the development wizard to create the project, the class PlugInApplication in the sample code is defined in PlugInApplication.cs, and the class Commands is defined in Commands.cs.

This sample code accomplishes two tasks: first, defining the PlugInApplication class that implements the IExtensionApplication interface, which includes callback functions for initialization and termination; second, defining the HelloCS command in the Commands class.

Next, we will explain each part of this code in detail.

1. Namespace References

The code begins with multiple using statements to import namespaces. ZWCAD-related namespaces include ZwSoft.ZwCAD.Runtime, ZwSoft.ZwCAD.ApplicationServices, ZwSoft.ZwCAD.Geometry, ZwSoft.ZwCAD.DatabaseServices, and ZwSoft.ZwCAD.EditorInput. The Runtime namespace is primarily used for plugin lifecycle control, ApplicationServices provides application-related services, Geometry offers geometric operations, DatabaseServices enables access to and manipulation of the drawing database, and EditorInput handles user interactions with the command line.

2. Assembly Attributes

Two assembly attributes are used in the code:

[assembly: ExtensionApplication(typeof(ZrxDotNetCSProject.PlugInApplication))]

This attribute instructs ZWCAD to call the Initialize method of the PlugInApplication class when loading the assembly (DLL) and the Terminate method when ZWCAD closes. This allows the development program to initialize and terminate operations at appropriate times.

[assembly: CommandClass(typeof(ZrxDotNetCSProject.Commands))]

This attribute identifies the command class within the assembly. ZWCAD scans the specified class (here, the Commands class) during plugin loading to find methods decorated with the [CommandMethod] attribute, thereby registering custom commands. This attribute is optional but improves loading efficiency by reducing the time ZWCAD spends scanning for [CommandMethod]-decorated methods.

3. PlugInApplication Class Analysis

The PlugInApplication class implements the IExtensionApplication interface, which requires two methods:

Initialize Method

Purpose: Automatically called when ZWCAD loads the assembly. Developers can add initialization code here, such as event registration, configuration file loading, or global variable initialization, to prepare for subsequent commands and internal data management.

Terminate Method

Purpose: Automatically called when ZWCAD closes. Developers can release resources, unregister events, or save states here to prevent resource leaks or unresolved states. For complex plugins, the Terminate method is essential, especially when handling large memory allocations or external system communications.

4. HelloCS Command

    [CommandMethod("HelloCS")]
    static public void HelloCS()
    {
        // Command implementation code
    }

CommandMethod Attribute

This attribute marks a method as a ZWCAD command. The method name does not directly determine the command name (though it coincidentally matches in this example); instead, the command name is specified by the string "HelloCS" in the attribute. When a user enters "HelloCS" in the command line, this method is invoked.

The CommandMethod attribute constructor has multiple overloads. Below are descriptions of the parameters:

globalName: The global name (string type), i.e., the command name (case-insensitive). This is a required parameter and must be unique; otherwise, command registration will fail.

localizedNameId: The localized name (string type), similar to globalName but intended for multilingual localization of the command name.

groupName: Group name (string type), the command group name. ZWCAD commands are managed through different command group names.

contextMenuExtensionType: Context menu type flag (Type type), defines the context menu behavior when the command is active.

helpFileName: Help file name (string type), contains the help topic to display when F1 is pressed while the command is active.

helpTopic: Help topic (string type), the topic within the help file.

flags: Command flags (CommandFlags type), defines the behavior of the command. Below are descriptions of some commonly used values of the CommandFlags type:

Enum Value Description
Modal Sets the command as a modal command, meaning it can only operate in the currently active document and cannot execute while other commands are running.
Session Sets the command execution level to application-level instead of the current document-level. Used when the command needs to execute across multiple documents or without any open documents. Use Document.LockDocument to lock the document when modifying document content.
Transparent Allows the command to run transparently, meaning it can execute while another command is in progress.
UsePickSet Allows the command to use the previously selected set of objects as input. Used when the command needs to access objects selected before execution.
NoPaperSpace Prohibits using this command from paper space.
NoTileMode Disables the command when the TILEMODE system variable is set to 1.

Command Internal Logic

Within the HelloCS method, the following steps are completed:

Get the current working database:

    Database db = HostApplicationServices.WorkingDatabase;

This retrieves the current drawing document's database object via HostApplicationServices.WorkingDatabase. The database object represents all drawing data in ZWCAD, such as entities, layers, and styles.

Get the current document:

    Document doc = Application.DocumentManager.GetDocument(db);

Retrieves the current document via DocumentManager based on the database object. The document object encapsulates properties and methods of the opened DWG file.

Get the editor object:

    ZwSoft.ZwCAD.EditorInput.Editor ed = doc.Editor;

Retrieves the Editor object from the document object. This object handles user interaction, command-line input, message display, and user input processing.

Output information to the command line:

    ed.WriteMessage("\nHello World!");

Finally, uses the Editor's WriteMessage method to output "Hello World!" in the command line window. The newline character \n ensures the message appears on a new line.

This code provides developers with a clear structural template. Developers can build upon this to add more complex business logic and operations, gradually creating fully functional secondary development programs with excellent user experience.
