Usage of Transactions

Detailed Explanation of Transactions

This chapter provides a detailed introduction to transactions in ZWCAD .NET development.

Definition of Transactions

In ZWCAD .NET development, transactions act as a "warehouse manager." When ZWCAD opens a DWG file, a Database object is generated in memory, containing all elements from the DWG file. To ensure the integrity and correctness of the DWG file and prevent data errors during access, ZWCAD introduces a transaction mechanism. The transaction manager supervises and controls access to and modifications of database objects, ensuring that all operations either fully succeed or roll back to their initial state.

Characteristics of Transactions

Atomicity

Operations within a transaction are either fully committed or entirely rolled back, ensuring database consistency. This means that if any error or exception occurs during execution, all executed operations are undone, restoring the database to its state before the transaction began.

Strict Management

The transaction mechanism protects database objects through strict management, preventing unauthorized access and modifications. Within a transaction, reading and modifying database objects must follow specific rules to ensure data security and integrity.

Full Supervision

When opening objects in writable mode, all modifications must be supervised throughout the transaction. The transaction manager records all changes and persists them to the database upon transaction commit.

The table below lists common interfaces used for transaction operations:

Interface Function
Database.TransactionManager Retrieves the transaction manager of the database object
TransactionManager.StartTransaction() Starts a transaction
Transaction.Commit() Commits the transaction
Transaction.Abort() Rolls back the transaction

How to Use Transactions

Transactions and Object Opening Modes

When operating on database objects within a transaction, you must specify the object's opening mode. Common modes include:

Read-only mode (OpenMode.ForRead): Opens an object in read-only mode, allowing access to its properties and geometric information but not modifications.

Writable mode (OpenMode.ForWrite): Opens an object in writable mode, enabling modifications. Modifications in this mode must be supervised throughout the transaction.

Committing and Rolling Back Transactions

Commit: After all operations in a transaction succeed, call Commit() to commit the transaction. Upon commit, all changes are persisted to the database, and the transaction manager releases locks on database objects.

Rollback: If an error or exception occurs, call Abort() to roll back the transaction. This undoes all operations, restoring the database to its pre-transaction state.

In .NET, the using statement is typically used to manage a transaction's lifecycle. The using statement ensures automatic resource cleanup via Dispose() and implicitly commits or rolls back the transaction based on whether an exception occurs.

    using (Transaction tr = db.TransactionManager.StartTransaction())
    {
        // Operations inside the transaction
        // ...
    
        // Commit the transaction
        tr.Commit();
    }
    // Here, the transaction is automatically disposed, and resources are released

Transactions and Error Handling

Errors and exceptions may occur during transaction execution. To ensure correctness and safety, implement appropriate error handling mechanisms.

Catching Exceptions: Use try-catch blocks to handle exceptions. In the catch block, decide whether to roll back the transaction or take other actions based on the exception type and severity.

Rollback: If an exception is caught and a rollback is needed, call Abort(). Log the error or notify the user after rollback.

    using (Transaction tr = db.TransactionManager.StartTransaction())
    {
        try
        {
            // Operations inside the transaction
            // ...

            // Commit the transaction
            tr.Commit();
        }
        catch (Exception ex)
        {
            // Roll back the transaction
            tr.Abort();
        }
    }

Nesting of Transactions

Nested transactions occur when a new transaction starts within an existing one. In ZWCAD .NET, the transaction manager supports nesting and stores nested transactions in a stack. The most recent transaction is at the top, accessible via TransactionManager.TopTransaction().

Commit: In nested transactions, each layer must be committed sequentially. Parent transactions must commit before child transactions take effect. If an inner transaction is aborted (e.g., due to an exception or Abort()), all operations within it are canceled, restoring objects to their state at the start of the transaction.

Nested Transaction Code Example

C#

[CommandMethod("NestedTransaction")]
public void NestedTransaction()
{
    Document zcDoc = Application.DocumentManager.MdiActiveDocument;
    Database zcCurDb = zcDoc.Database;
    // Get transaction manager
    ZwSoft.ZwCAD.DatabaseServices.TransactionManager zcTransMgr;
    zcTransMgr = zcCurDb.TransactionManager;
 
    // Add entities to the database through transactions
    using (Transaction zcTrans = zcTransMgr.StartTransaction())
    {
        BlockTable zcBlkTbl = zcTrans.GetObject(zcCurDb.BlockTableId, OpenMode.ForRead) as BlockTable;
        BlockTableRecord zcBlkTblRec = zcTrans.GetObject(zcBlkTbl[BlockTableRecord.ModelSpace], OpenMode.ForWrite) as BlockTableRecord;
        Line line = new Line(new Point3d(0, 0, 0), new Point3d(100, 100, 0));
        line.SetDatabaseDefaults();
        zcBlkTblRec.AppendEntity(line);
        zcTrans.AddNewlyCreatedDBObject(line, true);
        zcTrans.Commit();
    }
 
    // Modify existing entity data and roll back operations through nested transactions
    using (Transaction zcTrans1 = zcTransMgr.StartTransaction())
    {
        BlockTable zcBlkTbl = zcTrans1.GetObject(zcCurDb.BlockTableId, OpenMode.ForRead) as BlockTable;
        BlockTableRecord zcBlkTblRec = zcTrans1.GetObject(zcBlkTbl[BlockTableRecord.ModelSpace], OpenMode.ForWrite) as BlockTableRecord;
        // Traverse all entities in the block table record
        foreach (ObjectId entOid in zcBlkTblRec)
        {
            Entity ent = zcTrans1.GetObject(entOid, OpenMode.ForWrite) as Entity;
            // If the entity is not empty and the type is a straight line
            if (ent != null && ent.GetType() == typeof(Line))
            {
                // Convert entities to line type and set color index
                Line line = ent as Line;
                line.ColorIndex = 1;
            }
        }
 
        // Start a new nested transaction
        using (Transaction zcTrans2 = zcTransMgr.StartTransaction())
        {
            Line zcLine = new Line(new Point3d(0, 100, 0), new Point3d(100, 0, 0));
            zcLine.SetDatabaseDefaults();
            zcLine.ColorIndex = 3;
            zcBlkTblRec.AppendEntity(zcLine);
            zcTrans2.AddNewlyCreatedDBObject(zcLine, true);
            // Rollback nested transactions
            zcTrans2.Abort();
        }
 
        // Submit external affairs
        zcTrans1.Commit();
    }
}

VB

    <CommandMethod("NestedTransaction")>
    Public Sub NestedTransaction()
        Dim zcDoc As Document = Application.DocumentManager.MdiActiveDocument
        Dim zcCurDb As Database = zcDoc.Database

        ' Get transaction manager
        Dim zcTransMgr As ZwSoft.ZwCAD.DatabaseServices.TransactionManager = zcCurDb.TransactionManager

        ' Add entities to the database through transactions
        Using zcTrans As Transaction = zcTransMgr.StartTransaction()
            Dim zcBlkTbl As BlockTable = CType(zcTrans.GetObject(zcCurDb.BlockTableId, OpenMode.ForRead), BlockTable)
            Dim zcBlkTblRec As BlockTableRecord = CType(zcTrans.GetObject(zcBlkTbl(BlockTableRecord.ModelSpace), OpenMode.ForWrite), BlockTableRecord)

            Dim line As New Line(New Point3d(0, 0, 0), New Point3d(100, 100, 0))
            line.SetDatabaseDefaults()
            zcBlkTblRec.AppendEntity(line)
            zcTrans.AddNewlyCreatedDBObject(line, True)
            zcTrans.Commit()
        End Using

        ' Modify existing entity data and roll back operations through nested transactions
        Using zcTrans1 As Transaction = zcTransMgr.StartTransaction()
            Dim zcBlkTbl As BlockTable = CType(zcTrans1.GetObject(zcCurDb.BlockTableId, OpenMode.ForRead), BlockTable)
            Dim zcBlkTblRec As BlockTableRecord = CType(zcTrans1.GetObject(zcBlkTbl(BlockTableRecord.ModelSpace), OpenMode.ForWrite), BlockTableRecord)

            ' Traverse all entities in the block table record
            For Each entOid As ObjectId In zcBlkTblRec
                Dim ent As Entity = CType(zcTrans1.GetObject(entOid, OpenMode.ForWrite), Entity)

                ' If the entity is not empty and the type is a straight line
                If ent IsNot Nothing AndAlso ent.GetType() Is GetType(Line) Then
                    ' Convert entities to line type and set color index
                    Dim line As Line = CType(ent, Line)
                    line.ColorIndex = 1
                End If
            Next

            ' Start a new nested transaction
            Using zcTrans2 As Transaction = zcTransMgr.StartTransaction()
                Dim zcLine As New Line(New Point3d(0, 100, 0), New Point3d(100, 0, 0))
                zcLine.SetDatabaseDefaults()
                zcLine.ColorIndex = 3
                zcBlkTblRec.AppendEntity(zcLine)
                zcTrans2.AddNewlyCreatedDBObject(zcLine, True)

                ' Rollback nested transactions
                zcTrans2.Abort()
            End Using

            ' Submit external affairs
            zcTrans1.Commit()
        End Using
    End Sub

Operation result:

Modify existing entity data and roll back operations through nested transactions.

Best Practices for Transaction Management

Try to shorten the duration of the transaction as much as possible:

Long running transactions can consume database resources and reduce system performance. Therefore, the duration of transactions should be minimized as much as possible.

Avoid performing time-consuming operations in transactions:

If time-consuming operations (such as complex calculations or I/O operations) need to be performed within a transaction, consideration should be given to moving these operations to be executed outside of the transaction.

Reasonable use of nested transactions:

Although transactions support nesting, excessive nesting can lead to complex and difficult to maintain code. Therefore, the nested function of transactions should be used reasonably to ensure that the code is concise and clear.

Add appropriate error handling mechanisms:

Adding appropriate error handling mechanisms in transactions can ensure that transactions can be rolled back correctly and resources can be released in the event of an error.
